# MPC 动态避障依赖生成说明

本文说明如何在 ROS 工作区内，从本地 acados/CasADi 工具箱重新生成 MPC/NMPC 求解器、编译 `myrobot_mpc_avoidance`，并验证运行时没有使用桌面工具箱。

## 1. 功能边界

`myrobot_mpc_avoidance` 只负责在线动态避障：

- acados MPC/NMPC 求解器运行；
- 参考轨迹跟随、障碍物跟踪和动态避障；
- 死锁检测以及 `REPLAN_REQUIRED` 通知；
- 仿真障碍物发布。

初始参考轨迹和重规划参考轨迹不由本包的 MPC 求解器生成，而由 `myrobot_simulation` 中的 `birrt*` 规划节点生成并发布。收到 `REPLAN_REQUIRED` 后，仿真入口再次调用规划节点获取新的静态参考轨迹，MPC/NMPC 继续对该轨迹进行在线动态避障。

启动仿真入口：

```bash
source /opt/ros/humble/setup.bash
source ~/fairino_robotarm/install/setup.bash
ros2 launch myrobot_simulation mpc_avoidance_demo_sim.launch.py
```

## 2. 本地工具箱目录

ROS 只使用 `myrobot_mpc_ws/mpc_toolbox` 中的平台固定依赖，不依赖其他工作区或桌面目录中的 acados。当前目录结构为：

```text
~/fairino_robotarm/src/myrobot_mpc_ws/
├── mpc_toolbox/
│   ├── acados/
│   │   ├── bin/t_renderer
│   │   ├── include/
│   │   ├── lib/
│   │   └── interfaces/acados_template/
│   └── python/casadi/
└── myrobot_mpc_avoidance/
    ├── config/mpc_avoidance_params.yaml
    ├── scripts/
    │   ├── setup_acados_env.sh
    │   ├── acados_codegen_common.py
    │   ├── generate_acados_solver.py
    │   ├── generate_acados_nmpc_solver.py
    │   ├── acados_ocp_fairino_mpc.json
    │   └── acados_ocp_fairino_nmpc.json
    ├── c_generated_code/
    └── c_generated_code_nmpc/
```

需要具备 Linux x86_64、ROS 2 Humble、Python 3、NumPy、C/C++ 编译器以及本地 `mpc_toolbox`。MATLAB 不参与 ROS 求解器生成和 ROS 动态避障运行。

Ubuntu 安装缺少的 acados Python 模板依赖：

```bash
sudo apt install -y python3-deprecated
```

`deprecated` 是 `acados_template` 的 Python 依赖，不来自旧的桌面工具箱；加载脚本会在缺失时停止并给出该命令。

## 3. 从头生成 MPC/NMPC

以下命令从 ROS 工作区根目录执行。

### 3.1 加载环境并检查本地依赖

```bash
cd ~/fairino_robotarm
source /opt/ros/humble/setup.bash
source install/setup.bash

test -x src/myrobot_mpc_ws/mpc_toolbox/acados/bin/t_renderer
test -d src/myrobot_mpc_ws/mpc_toolbox/acados/include
test -d src/myrobot_mpc_ws/mpc_toolbox/acados/lib
test -d src/myrobot_mpc_ws/mpc_toolbox/acados/interfaces/acados_template
test -d src/myrobot_mpc_ws/mpc_toolbox/python/casadi
```

进入包目录并加载本地工具链：

```bash
cd src/myrobot_mpc_ws/myrobot_mpc_avoidance
source scripts/setup_acados_env.sh
```

检查环境变量和 Python 实际导入位置：

```bash
printf 'ACADOS_INSTALL_DIR=%s\nACADOS_SOURCE_DIR=%s\nCASADI_DIR=%s\n' \
  "$ACADOS_INSTALL_DIR" "$ACADOS_SOURCE_DIR" "$CASADI_DIR"

python3 -c 'import acados_template, casadi; print(acados_template.__file__); print(casadi.__file__)'
```

上述路径必须位于：

```text
~/fairino_robotarm/src/myrobot_mpc_ws/mpc_toolbox/
```

两个生成脚本还会自行计算并强制设置包相邻的本地工具箱路径，因此即使当前 shell 继承了错误的外部变量，也不会静默生成到其他 acados 目录。

### 3.2 生成 MPC

```bash
python3 scripts/generate_acados_solver.py
```

该脚本生成：

- `c_generated_code/` 中的 MPC C 源码、头文件和 Makefile；
- `scripts/acados_ocp_fairino_mpc.json` 中的 MPC OCP 生成元数据。

### 3.3 生成 NMPC

```bash
python3 scripts/generate_acados_nmpc_solver.py
```

该脚本生成：

- `c_generated_code_nmpc/` 中的 NMPC C 源码、头文件和 Makefile；
- `scripts/acados_ocp_fairino_nmpc.json` 中的 NMPC OCP 生成元数据。

生成过程中的 API 兼容性处理由 `scripts/acados_codegen_common.py` 统一完成。出现 acados 版本迁移提示属于生成器提示；出现导入路径、模板、渲染器或编译错误才需要停止排查。

## 4. JSON 文件是否需要删除

`acados_ocp_fairino_mpc.json` 和 `acados_ocp_fairino_nmpc.json` 是 acados 代码生成阶段产生的 OCP 配置和元数据归档，不是独立的运行时库，也不是需要手工编辑的动力学模型源文件。

不需要在重新生成前删除它们。对应生成脚本会覆盖对应 JSON，并更新对应的生成目录：

| 文件 | 负责脚本 | 生成目录 |
| --- | --- | --- |
| `acados_ocp_fairino_mpc.json` | `generate_acados_solver.py` | `c_generated_code/` |
| `acados_ocp_fairino_nmpc.json` | `generate_acados_nmpc_solver.py` | `c_generated_code_nmpc/` |

规则如下：

- 只修改 MPC 模型时，只运行 MPC 生成脚本；
- 只修改 NMPC 模型时，只运行 NMPC 生成脚本；
- acados/CasADi API 或共享代码变化时，两个脚本都运行；
- 两个 JSON 不能合并，它们对应不同的 OCP、代价函数和生成输出；
- 需要干净重建时，清理编译产物即可，保留 JSON、C 源码、头文件和 Makefile。

只清理生成目录中的二进制编译产物：

```bash
find c_generated_code c_generated_code_nmpc -type f \\
  \( -name '*.o' -o -name '*.so' \) -delete
```

如果确实修改了模型并希望重新导出所有 C 源码，直接再次运行两个生成脚本即可，不要手工编辑 JSON。

## 5. 编译 ROS 包

回到工作区根目录：

```bash
cd ~/fairino_robotarm
source /opt/ros/humble/setup.bash
colcon build --packages-select myrobot_mpc_avoidance --symlink-install
source install/setup.bash
```

CMake 会在需要时调用两个本地生成脚本，然后编译 MPC/NMPC C 源码并链接本地 acados 库。

检查安装节点的 RPATH 和动态库解析：

```bash
readelf -d install/myrobot_mpc_avoidance/lib/myrobot_mpc_avoidance/mpc_avoidance_node \\
  | grep -E 'RPATH|RUNPATH'

ldd install/myrobot_mpc_avoidance/lib/myrobot_mpc_avoidance/mpc_avoidance_node \\
  | grep -E 'acados|hpipm|blasfeo|qpOASES'
```

`libacados.so`、`libhpipm.so`、`libblasfeo.so` 和 `libqpOASES_e.so` 必须解析到：

```text
~/fairino_robotarm/src/myrobot_mpc_ws/mpc_toolbox/acados/lib/
```

## 6. 运行动态避障

```bash
cd ~/fairino_robotarm
source /opt/ros/humble/setup.bash
source install/setup.bash
ROS_LOG_DIR=/tmp/ros_launch_logs \\
ros2 launch myrobot_simulation mpc_avoidance_demo_sim.launch.py
```

关键运行链路为：

```text
birrt* 初始规划
        ↓
/planned_trajectory
        ↓
mpc_avoidance_node / NMPC
        ↓
动态障碍物跟踪与在线避障
        ↓
REPLAN_REQUIRED
        ↓
birrt* 重规划
```

`solver_type` 可选择 `mpc` 或 `nmpc`。如果没有初始参考轨迹，应先检查 `myrobot_simulation` 的轨迹规划节点、规划管线和 `/planned_trajectory`，而不是删除或重新生成 JSON。

## 7. 常见故障排查

### Python 导入了错误的 acados 或 CasADi

重新执行：

```bash
cd ~/fairino_robotarm/src/myrobot_mpc_ws/myrobot_mpc_avoidance
source scripts/setup_acados_env.sh
python3 scripts/generate_acados_solver.py
```

检查输出中的 `Using ACADOS_INSTALL_DIR`、`Using acados_template` 和 `Using CasADi`。三个路径都必须指向 `src/myrobot_mpc_ws/mpc_toolbox`。

### CMake 使用了旧缓存

检查 `build/myrobot_mpc_avoidance` 中的 CMake 配置和 `ACADOS_INSTALL_DIR`。确认本地路径后重新执行：

```bash
colcon build --packages-select myrobot_mpc_avoidance --symlink-install
```

如果是旧构建树缓存导致的路径不一致，只清理该包的 `build/myrobot_mpc_avoidance` 后重新构建，不要删除整个工作区。

### 运行时解析到错误动态库

优先以 `readelf` 和 `ldd` 的实际结果为准。确认安装节点的 RPATH 指向本地 `mpc_toolbox/acados/lib`，并重新加载 `install/setup.bash`。

### 没有初始轨迹或没有重规划轨迹

确认 `mpc_avoidance_demo_sim.launch.py` 已启动 `trajectory_plan_node_sim`、规划器使用 `birrt*`，并检查 `/planned_trajectory` 与 `REPLAN_REQUIRED` 相关话题。MPC 包不包含静态规划器插件链。

### launch 很久没有继续启动

检查 ROS 日志目录是否可写。诊断时可使用：

```bash
ROS_LOG_DIR=/tmp/ros_launch_logs \\
ros2 launch myrobot_simulation mpc_avoidance_demo_sim.launch.py --show-args
```

这可以避免默认日志目录权限问题干扰 launch 参数检查。
