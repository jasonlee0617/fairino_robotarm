# myrobot_planning_ros 包详细说明

本文档说明 `myrobot_planning_ros` 包下各文件作用、模块联系与运行链路。该包负责把 `myrobot_planning_core` 算法接入 ROS2/MoveIt2。

---

## 1. 包定位

`myrobot_planning_ros` 是 `myrobot_planning_core` 的 ROS 适配层，提供：
- MoveIt 规划插件（PlannerManager）
- MoveIt IK 插件
- 与 PlanningScene 的碰撞检查桥接
- 独立规划节点与 launch/demo 配置

它的核心职责是：把 MoveIt 的请求转换为 core 算法输入，再把规划结果回写为 MoveIt 标准响应。

---

## 2. 目录与文件作用

## 2.1 根文件

- `CMakeLists.txt`  
  构建 ROS 共享库（插件）和可执行节点 `standalone_planner`；安装 launch/plugins/docs。
  本包不再安装算法 YAML，算法调参文件统一由 `myrobot_planning_core/config/` 提供。

- `package.xml`  
  ROS 与 MoveIt 依赖声明。

---

## 2.2 头文件 `include/myrobot_planning_ros/`

- `fairino_planner_manager.h`  
  MoveIt 规划插件主入口定义。实现 `planning_interface::PlannerManager` 以及上下文创建逻辑。

- `fairino_ik_plugin.h`  
  MoveIt IK 插件定义，对接 `kinematics::KinematicsBase` 接口。

- `moveit_collision_checker.h`  
  `myrobot_planning_core::collision::CollisionInterface` 的 MoveIt 实现，基于 `PlanningScene` 做碰撞判定。

---

## 2.3 源码 `src/`

- `fairino_planner_manager.cpp`  
  **核心文件**。主要工作：
  1. 解析 MoveIt 请求（起点、目标、约束）
  2. 笛卡尔目标时通过当前 `move_group` 的 MoveIt kinematics plugin 计算目标关节
  3. 创建并配置规划算法（`mire_biait*` / `aapf_birrt*` / `birrt*` / `rrt` / `rrt*` / `informed_rrt*` / `prm`，不兼容旧大写 planner_id）
  4. 注入 `MoveItCollisionChecker`
  5. 执行规划 + 路径后处理（shortcut/smooth）
  6. 组装 `MotionPlanResponse`

- `fairino_ik_plugin.cpp`  
  IK 插件实现，向 MoveIt 暴露 Fairino IK 求解能力。

- `config/parameter_loader.cpp`  
  ROS 参数读取唯一入口。它把 ROS 参数服务器中的值转换为
  `myrobot_planning_core` 的 `PlannerConfig`、`IKSelectParams` 和本包的 `PipelineOptions`。
  算法层和插件层不再各自手写一套 `declare_parameter()` 默认值。

- `moveit_collision_checker.cpp`  
  碰撞桥接实现，把 core 的状态碰撞查询映射到 MoveIt `PlanningScene`。

- `standalone_planner_node.cpp`  
  独立运行节点（非 MoveIt 插件路径）示例/调试入口。

---

## 2.4 参数归属

`myrobot_planning_ros` 不拥有算法调参 YAML。统一规则如下：

- canonical YAML 在 `myrobot_planning_core/config/`
  - `common_planning_params.yaml`：公共层，保留路径优化、轨迹输出、PlanningScene 障碍物输入等参数。
  - `mire_biait_star_params.yaml`：`mire_biait*` 的批图、多 IK 根及后解引导参数。
  - `aapf_birrt_star_params.yaml`：`aapf_birrt*` 专属自适应采样参数。
  - `birrt_star_params.yaml`：`birrt*` 最小双向 RRT* 基线参数。
  - `rrt_params.yaml`：`rrt` 标准单树、无重连基线参数。
  - `rrt_star_params.yaml`：`rrt*` 最小单树 RRT* 基线参数。
  - `prm_params.yaml`：`prm` 的最近邻 roadmap 参数。
  - `ik_params.yaml`：IK 候选筛选、奇异规避、分支连续性、工具模型覆盖等 IK 参数。
- ROS 包只负责加载和适配参数：
  - `myrobot_planning_ros/config/parameter_loader.*` 是唯一 ROS 参数读取入口。
  - 读取结果进入 core 的 typed config：`PlannerConfig`、`IKSelectParams`。
  - pipeline 级参数进入 `PipelineOptions`，再下发给 core 的路径后处理和轨迹生成。

参数命名约定：
- IK 参数统一命名空间：`fairino.ik.*`
- 规划策略参数统一命名空间：`fairino.sampling.*`、`fairino.termination.*`、`fairino.orientation.*`、
  `fairino.fallback.*`、`fairino.optimizer.*`、`fairino.trajectory.*`、`fairino.pipeline.*`
- `fairino.ik.tool_model_override` 为正式键；`tool_model_override` 仅兼容回退。

## 2.5 启动文件 `launch/`

- `planning_pipeline.launch.py`  
  占位文件（当前为空壳，不是实际生产入口）。

- `demo.launch.py`  
  占位文件（当前为空壳，不是实际生产入口）。

实际集成说明：
- 真实上层 launch 应从 `myrobot_planning_core` 包加载 `common_planning_params.yaml`、`mire_biait_star_params.yaml`、`aapf_birrt_star_params.yaml`、`birrt_star_params.yaml`、`rrt_params.yaml`、`rrt_star_params.yaml` 和 `ik_params.yaml`。
- `fairino_arm_moveit_config/config/fairino_planning.yaml` 可作为 MoveIt pipeline 聚合配置存在，
  但不应成为另一套算法默认值来源。
- 推荐参数覆盖顺序：先加载规划参数，再加载 IK 参数，最后加载场景或实验专用覆盖。

### launch 加载示例

`myrobot_planning_ros` 本身不保存算法 YAML。启动 `move_group_fairino` 时，应从
`myrobot_planning_core` 包定位参数文件：

```python
from launch_ros.actions import Node
from ament_index_python.packages import get_package_share_directory
import os

planning_core_share = get_package_share_directory("myrobot_planning_core")
common_planning_params = os.path.join(planning_core_share, "config", "common_planning_params.yaml")
mire_params = os.path.join(planning_core_share, "config", "mire_biait_star_params.yaml")
aapf_params = os.path.join(planning_core_share, "config", "aapf_birrt_star_params.yaml")
birrt_params = os.path.join(planning_core_share, "config", "birrt_star_params.yaml")
rrt_params = os.path.join(planning_core_share, "config", "rrt_star_params.yaml")
ik_params = os.path.join(planning_core_share, "config", "ik_params.yaml")

move_group_node_fairino = Node(
    package="moveit_ros_move_group",
    executable="move_group",
    namespace="move_group_fairino",
    parameters=[
        moveit_config.to_dict(),
        planning_params,
        aapf_params,
        birrt_params,
        rrt_params,
        ik_params,
        {"use_sim_time": True},
    ],
)
```

参数文件必须注入到真正加载 `myrobot_planning_ros` 插件的那个 `move_group` 节点上。
双 move_group 架构下，一般是：

- `/move_group_fairino/move_group`：加载 Fairino IK，可同时加载 `fairino`/`ompl` planning pipeline。
- `/move_group_kdl/move_group`：加载 KDL kinematics；当 profile 开启 `enable_fairino_pipeline_on_kdl` 时，也加载 Fairino pipeline 和 core YAML。

启动后可用以下命令验证：

```bash
ros2 param list /move_group_fairino/move_group | grep fairino
ros2 param list /move_group_kdl/move_group | grep fairino
ros2 param get /move_group_fairino/move_group fairino.algorithms.birrt_star.max_iterations
ros2 param get /move_group_fairino/move_group fairino.algorithms.rrt_star.max_iterations
ros2 param get /move_group_fairino/move_group fairino.ik.w_sing
```

如果参数不存在，说明 YAML 没有被 launch 加进对应节点。此时应检查 `gazebo.launch.py`、
`gazebo_yolo.launch.py` 或其它上层 launch 中的 `parameters=[...]` 列表。

## 3. 模块关系与数据流

## 3.1 MoveIt 规划链（主链）

1. MoveIt 收到规划请求（start/goal/constraints）  
2. `fairino_planner_manager` 创建 `PlanningContext`  
3. 若 goal 是笛卡尔位姿：
   - 先走当前 `move_group` 加载的 MoveIt kinematics plugin，例如 `/move_group_kdl` 使用 KDL，`/move_group_fairino` 使用 Fairino IK
   - 将求出的 `q_goal` 作为 exact joint target 交给 Fairino planner
4. 创建 `MoveItCollisionChecker` 并注入 core 算法  
5. 调 core 的 `AapfBiRRTStar` / `BiRRTStar` / `RRTStar::plan()`
6. 调 core 轨迹后处理（shortcut/smoother）  
7. 回填 MoveIt `MotionPlanResponse`

## 3.2 IK 链

`ik_plugin` 只决定连接哪个 `move_group`/IK 插件；`planning_pipeline_id` 只决定 MoveIt planning pipeline。

- `kdl + fairino`：请求进入 `/move_group_kdl`，Pose goal 先由 KDL `setFromIK()` 转为 `q_goal`，再由 Fairino pipeline 规划。
- `fairino + ompl`：请求进入 `/move_group_fairino`，OMPL Pose goal 使用 Fairino IK 插件。
- Fairino IK 插件链路：MoveIt IK 请求 -> `fairino_ik_plugin` -> core `fairino_ik` -> 返回关节解。

## 3.3 碰撞链

core 规划状态查询 -> `moveit_collision_checker` -> MoveIt `PlanningScene` 判定

## 3.4 参数链

```text
myrobot_planning_core/config/common_planning_params.yaml
myrobot_planning_core/config/aapf_birrt_star_params.yaml
myrobot_planning_core/config/birrt_star_params.yaml
myrobot_planning_core/config/rrt_star_params.yaml
myrobot_planning_core/config/ik_params.yaml
        |
        | launch / MoveIt pipeline 参数注入到对应 move_group 节点
        v
ROS 参数服务器
        |
        | myrobot_planning_ros/config/parameter_loader.*
        v
PlannerConfig / IKSelectParams / PipelineOptions
        |
        +--> FairinoPlannerManager -> mire_biait*/aapf_birrt*/birrt*/rrt/rrt*
        |
        +--> FairinoIKPlugin -> FairinoIK + IKSelector
```

这条链路体现了本轮重构后的职责边界：

- `core` 定义“有哪些可调参数、默认含义是什么、算法如何使用”。
- `ros` 定义“如何从 ROS 参数服务器读取并注入 core”。
- launch/MoveIt 配置定义“本次运行加载哪组参数”。

---

## 4. 与 myrobot_planning_core 的关系

- `myrobot_planning_core`：算法与数学核心（不依赖 ROS 业务流程）
- `myrobot_planning_ros`：ROS/MoveIt 适配与插件封装

可以理解为：
- core 负责“怎么规划”
- ros 包负责“怎么接入系统、怎么收发请求/响应”

---

## 5. 常见开发入口建议

1. 调算法行为：优先看 `myrobot_planning_core`（RRT*/采样/后处理）  
2. 调 MoveIt 请求解析与响应：看 `fairino_planner_manager.cpp`  
3. 调碰撞判定一致性：看 `moveit_collision_checker.cpp`  
4. 调 IK 插件行为：看 `fairino_ik_plugin.cpp` +
   `myrobot_planning_core/config/ik_params.yaml`

---

## 6. 维护注意点

- 修改插件类名/命名空间时，必须同步更新 `plugins/myrobot_planning_plugins.xml`。  
- 若新增算法参数，优先进入对应的 `myrobot_planning_core/config/*_params.yaml`
  与 core typed config，
  再在 `parameter_loader.*` 增加读取映射。  
- 算法参数按 planner 拆分，IK 参数只放 `myrobot_planning_core/config/ik_params.yaml`，避免双轨漂移。  
- `standalone_planner_node` 仅用于验证与调试，不应替代 MoveIt 主链行为定义。
